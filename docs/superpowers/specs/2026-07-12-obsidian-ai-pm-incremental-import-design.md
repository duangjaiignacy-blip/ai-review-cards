# Obsidian AI 产品经理资料增量导入设计

## 目标

在不改动现有卡片 ID、题库行为和用户本地复习记录的前提下，将 Obsidian 个人知识库中尚未覆盖的 2026-07-06 AI 产品班资料完整转成复习卡，并加入 AI Review Cards。

本次覆盖两节课程：

- 上午：AI 产品经理求职培训课程
- 中午：AI 产品经理求职简历与面试准备

预计新增 50–80 张卡片，以实际去重后的有效知识点数量为准，不为满足数量制造重复卡。

## 数据来源与边界

优先读取每节课的四类结构化资料：

1. 总结版
2. 老师强调
3. 面试要点
4. 重点知识点

四类资料交叉去重。原版逐字稿只在结构化资料存在上下文缺失或含义不清时定向核对，不作为批量提取主源。

不修改 Obsidian 文件，不把课程原文复制进 Git 仓库。仓库中仅保存转化后的复习卡，避免引入私人资料和无关长文本。

## 增量与去重策略

- 保留当前 243 张卡片及全部原 ID。
- 新卡使用稳定的 `kc-0706-*` ID 前缀。
- 先按核心结论去重，再按题目表达去重；同一知识点在多个来源出现时合并为一张更完整的卡。
- 若知识点与旧卡完全重复，不新增；若 7 月 6 日提供了新的求职场景、回答框架或操作细节，则新增场景化卡片。
- 不调整旧卡的 SRS 初始值，避免影响浏览器中按 ID 保存的复习进度。

## 卡片设计

沿用现有数据结构：

- `choice`：概念辨析、流程判断、易错项。
- `qa`：项目表达、简历策略、求职方法和面试话术。
- `recall`：需要完整复述的框架、步骤、检查清单和回答结构。

每张卡至少包含：

- 唯一 `id`
- `type`
- `topic`
- 可追溯的 `source`
- `cat`（课程或面试）
- 问题 `front`
- 标准答案 `back`
- 默认 SRS 状态

选择题还需包含 `options`、合法的 `answer` 索引和解释 `explain`。适合生活化记忆的知识点补充 `analogy`，不强制为不适合类比的内容编造类比。

## 内容组织

新增内容按以下主题归类：

- AI 产品项目证据链与项目文档
- 数据埋点、模型评测与 AI PRD
- 内部资源库和求职资料库建设
- 飞书在线简历与 PDF 简历
- 自我介绍与项目讲述
- 面试准备、面试复盘和分阶段投递
- 面试官视角、招聘信号与求职执行策略

其中与招聘、简历、自我介绍、面试回答及投递有关的卡标为 `面试`；通用产品知识和项目方法标为 `课程`。

## 实施方式

卡片继续写入现有 `index.html` 的 `CARDS` 数组，以保持静态单页部署方式和现有运行逻辑不变。本次不拆分数据文件，不做无关重构。

同步更新 `scripts/validate-cards.mjs`：

- 卡片总数改为新增后的精确数量。
- 添加若干 7 月 6 日关键卡 ID 的存在性断言。
- 面试卡数量阈值按新增结果提高。
- 保留唯一 ID、类型、必填字段和选择题答案范围校验。

## 验证与验收

实施完成后执行：

1. `node scripts/validate-cards.mjs`
2. 检查所有新 ID 唯一且均以 `kc-0706-` 开头。
3. 核对两节课及四类结构化来源中的有效知识点均已覆盖或有明确去重归并。
4. 在浏览器中打开页面，确认题库加载、课程/面试筛选、选择题作答及翻卡流程正常。
5. 确认 Git diff 未包含 Obsidian 原文、隐私数据或无关改动。

验收标准是：验证脚本通过、页面核心流程正常、现有卡片 ID 未变化、7 月 6 日有效新知识完整覆盖且无明显重复。
